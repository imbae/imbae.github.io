# 02. 사이트가 어떻게 만들어지나

내용을 고치기 전에, "고친 게 어떻게 웹 페이지가 되는지" 큰 그림을 잡는 문서입니다.

---

## 1. 웹 페이지의 재료 3가지

브라우저가 이해하는 건 결국 이 세 가지입니다.

| 언어 | 역할 | 비유 |
|------|------|------|
| **HTML** | 내용과 구조 (제목, 문단, 목록, 링크…) | 건물의 골조 |
| **CSS** | 생김새 (색, 글꼴, 간격, 배치) | 인테리어·페인트 |
| **JavaScript(JS)** | 움직임 (클릭하면 메뉴 열림 등) | 전기·자동문 |

이 사이트의 CSS는 `src/assets/css/`에, JS는 `src/assets/js/main.js`에 있습니다.
디자인을 크게 바꿀 게 아니면 여기는 건드릴 일이 거의 없습니다.

---

## 2. "정적 사이트" 와 "빌드"

### 정적(static) 사이트란

방문자가 페이지를 열 때 서버가 계산하는 게 **없는** 사이트입니다. 미리 만들어
둔 HTML 파일을 그냥 보내줍니다. 그래서:
- 빠르고, 서버 비용이 안 들고(무료 GitHub Pages), 해킹당할 표면이 작습니다.
- 대신 "로그인한 사용자만 보이는 글" 같은 건 불가능합니다. (우리 사이트엔 필요 없음)

### 그런데 왜 `src/`와 `_site/`가 따로 있나

HTML을 손으로 다 쓰면, 페이지마다 똑같은 머리말·꼬리말·메뉴를 복붙해야 합니다.
글 하나 추가할 때마다 목록 페이지도 손으로 고쳐야 하고요.

그래서 **재료**(`src/`)를 두고, **Eleventy**라는 도구가 재료를 조립해서
**완성품**(`_site/`)을 만듭니다. 이 조립 과정이 "빌드"입니다.

```
src/  (내가 고치는 곳)          →   Eleventy(빌드)   →   _site/  (자동 생성, 실제 배포물)
  글 마크다운, 데이터 파일,                                  완성된 .html 파일들
  머리말/꼬리말 틀 1개씩
```

- 나는 **`src/`만** 고칩니다.
- `_site/`는 절대 손대지 않습니다 (다음 빌드 때 통째로 새로 만들어짐).
- `git push` 하면 GitHub의 서버가 `npm run build`를 대신 돌려서 `_site/`를 만들고
  그걸 배포합니다.

---

## 3. 조립에 쓰이는 재료들

### 마크다운(Markdown, `.md`)

글을 쉽게 쓰는 문법입니다. HTML을 몰라도 됩니다.

```markdown
## 소제목

**굵게**, *기울임*, [링크 텍스트](https://example.com)

- 목록 1
- 목록 2

1. 순서 목록
2. 다음

> 인용문

`코드 조각`
```

빌드하면 이게 알아서 `<h2>`, `<strong>`, `<ul>` 같은 HTML로 바뀝니다.

### 프론트매터(front matter)

마크다운 파일 **맨 위**에 `---` 로 감싼 부분. "이 글의 정보"를 적습니다.

```markdown
---
title: 글 제목
date: 2026-01-15
tags: [Flutter, 회고]
---

여기서부터 본문...
```

`title`, `date` 같은 이름들은 이 프로젝트가 정해둔 것입니다. 어떤 이름을
써야 하는지는 [03. 콘텐츠 수정하기](03-editing-content.md)에 정리돼 있습니다.

### 데이터 파일 (`.js`)

목록으로 관리하는 게 나은 것(프로젝트 목록, 책 목록)은 마크다운 대신
JavaScript 배열로 둡니다. `src/_data/` 폴더에 있습니다.

```js
// src/_data/books.js
export default [
  { title: "책 이름", author: "지은이", status: "reading" },
  { title: "다른 책", author: "다른 이", status: "done", rating: 5 },
];
```

문법이 낯설어도, **기존 항목을 복사해서 값만 바꾸는** 수준이면 충분합니다.
쉼표·중괄호 위치만 기존과 똑같이 맞추면 됩니다.

### 템플릿 (`.njk` — Nunjucks)

"머리말/꼬리말/메뉴가 든 HTML 틀"입니다. `{{ }}` 안에 값을 꽂고,
`{% for %}`로 목록을 반복합니다.

```nunjucks
<h1>{{ title }}</h1>
{% for book in books %}
  <li>{{ book.title }}</li>
{% endfor %}
```

`src/_includes/`에 틀이 있습니다. **여기는 웬만하면 안 건드려도** 콘텐츠는
다 고칠 수 있습니다. 디자인·레이아웃을 바꿀 때만 봅니다.

## 4. 폴더 구조 한눈에

```
imbae.github.io/
├── src/                     ★ 내가 고치는 모든 것
│   ├── _data/               목록형 데이터
│   │   ├── site.js          이름·이메일·GitHub·메뉴·공통 문구
│   │   ├── projects.js      프로젝트 목록 (제목·기간·스택·상태)
│   │   ├── books.js         독서 기록
│   │   └── projectSets.js   projects.js를 자동 가공 (안 건드림)
│   │
│   ├── _includes/           HTML 틀 (레이아웃, 머리말/꼬리말) — 디자인 담당
│   │   ├── layouts/
│   │   └── partials/
│   │
│   ├── assets/              CSS·JS·이미지 — 디자인 담당
│   │   ├── css/
│   │   ├── js/main.js
│   │   └── images/          (프로필 사진 등 넣을 자리)
│   │
│   ├── ko/                  한국어 페이지 → 사이트에서 "/..." 주소
│   │   ├── index.njk        홈
│   │   ├── about.md  now.md  uses.md
│   │   ├── work/index.njk        업무 프로젝트 "목록" 페이지
│   │   ├── projects/index.njk    개인 프로젝트 "목록" 페이지
│   │   ├── notes/index.njk       글 "목록" 페이지
│   │   ├── bookshelf/index.njk   책장 페이지
│   │   └── portfolio/index.njk   포트폴리오 페이지
│   │
│   ├── en/                  영어 페이지 → "/en/..." 주소 (ko와 같은 구성)
│   │
│   ├── notes/               ★ 글 본문
│   │   ├── ko/*.md
│   │   └── en/*.md
│   │
│   ├── projects/            ★ 프로젝트 "상세" 본문
│   │   ├── ko/<slug>.md
│   │   └── en/<slug>.md
│   │
│   ├── feed/                RSS 파일 (안 건드림)
│   ├── root/robots.txt      검색엔진용 (안 건드림)
│   ├── sitemap.njk  404.njk (안 건드림)
│   └── *.11tydata.js        폴더별 규칙 파일 (안 건드림 — 아래 설명)
│
├── _site/                   빌드 결과물 (자동 생성, 손대지 않음, git 제외)
├── node_modules/            내려받은 패키지 (자동, 손대지 않음, git 제외)
├── docs/guides/             ← 지금 읽는 문서들
├── eleventy.config.js       빌드 설정 (고급)
├── package.json             필요한 패키지 목록
└── CLAUDE.md                압축 참고 문서
```

### `*.11tydata.js` 가 뭔가요

`src/ko/ko.11tydata.js` 처럼 폴더 이름이 붙은 파일은 **그 폴더 안 모든 파일에
공통으로 적용되는 규칙**입니다. 예를 들어 `src/ko/` 안의 파일은 전부
"언어=한국어, 주소에서 `/ko` 떼기" 규칙을 자동으로 받습니다.

덕분에 `src/ko/about.md`는 주소가 `/about/`, `src/en/about.md`는 `/en/about/`이
됩니다. 이 파일들은 한 번 만들어두면 고칠 일이 없습니다.

## 5. "목록 페이지" 와 "상세 페이지"

프로젝트와 글은 두 종류의 페이지로 나옵니다.

| | 목록 페이지 | 상세 페이지 |
|---|---|---|
| 예 | `/work/`, `/notes/` | `/work/bgcs/`, `/notes/어떤-글/` |
| 만들어지는 곳 | `src/ko/work/index.njk` 등 (틀) | 데이터 + 마크다운 본문에서 **자동** |
| 내가 하는 일 | 거의 없음 | 여기에 내용을 씀 |

즉 **글이나 프로젝트를 하나 추가하면 목록에도 자동으로 나타납니다.**
목록 페이지를 손으로 고칠 필요가 없습니다.

---

## 6. 한국어 / 영어는 왜 파일이 따로인가

이 사이트는 두 언어를 (자동 번역이 아니라) **각각 따로 씀** 방식입니다.

- 한국어: `src/ko/...`, `src/notes/ko/...`, `src/projects/ko/...`
- 영어: `src/en/...`, `src/notes/en/...`, `src/projects/en/...`

새 페이지를 만들면 **양쪽 다** 만들어야 합니다. 한쪽만 있으면 상단의
언어 전환 링크(한국어 ↔ English)가 없는 페이지로 이동하게 됩니다.

영어를 당장 못 쓰겠으면: 일단 한국어만 추가하고, 영어판은 나중에 채워도
사이트는 정상 작동합니다. (글의 경우 목록에 "Korean only"로 표시됨)
