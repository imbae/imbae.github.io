# 01. 시작하기

이 문서는 **처음 한 번** 하는 준비 작업입니다. 한 번 해두면 다음부터는
`npm run dev` 한 줄이면 됩니다.

---

## 0. 용어 먼저

| 용어 | 쉽게 말하면 |
|------|-------------|
| **터미널**(Terminal) | 명령어를 타이핑해서 컴퓨터에 시키는 검은 창. Windows에서는 "PowerShell" 또는 "명령 프롬프트". VS Code 안에도 `보기 → 터미널`로 열 수 있습니다. |
| **Node.js** | 브라우저 밖에서 JavaScript를 실행해 주는 프로그램. 이 사이트를 만드는 도구(Eleventy)가 Node 위에서 돌아갑니다. |
| **npm** | Node를 설치하면 같이 깔리는 도구. "이 프로젝트에 필요한 라이브러리들을 받아와" 같은 걸 시킵니다. (`npm` = Node Package Manager) |
| **패키지 / 라이브러리** | 남이 만들어 둔 코드 묶음. 우리는 `Eleventy` 같은 패키지를 받아서 씁니다. |
| **빌드**(build) | `src/` 폴더의 재료 파일들을 실제 웹 페이지(`_site/` 폴더의 HTML)로 굽는 과정. |
| **로컬**(local) | 내 컴퓨터. "로컬에서 띄운다" = 인터넷에 올리기 전에 내 컴퓨터에서 미리 본다. |
| **배포**(deploy) | 만든 결과물을 인터넷(GitHub Pages)에 올려서 누구나 볼 수 있게 하는 것. |

## 1. 필요한 프로그램

### Node.js (이미 설치돼 있음)

이 PC에는 이미 설치했습니다 (버전 24, `C:\Program Files\nodejs`).
확인하려면 **새 터미널**을 열고:

```bash
node -v
```

`v24.xx.x` 처럼 나오면 정상입니다.

> **"node를 찾을 수 없습니다"가 나오면?**
> Node를 설치하기 *전에* 열어둔 터미널이라 그렇습니다. 그 터미널을 닫고
> **새 터미널을 열면** 해결됩니다. (VS Code도 완전히 껐다 켜기)

나중에 다른 PC에서 처음 세팅한다면: <https://nodejs.org> 에서 "LTS" 버전을
받아 설치하면 됩니다.

### Git (이미 설치돼 있음)

코드 변경 이력을 저장하고 GitHub에 올리는 도구입니다. 이미 쓰고 있으니
설명은 생략합니다.

### 편집기

VS Code를 권장합니다. 확장 프로그램은 필수는 아니지만 있으면 편한 것:
- **Nunjucks** (템플릿 문법 색칠)
- **EditorConfig** (들여쓰기 자동 맞춤 — 이 저장소에 설정 파일 있음)

## 2. 프로젝트 준비 (최초 1회)

터미널을 열고 프로젝트 폴더로 이동합니다:

```bash
cd D:\source\imbae.github.io
```

필요한 패키지를 내려받습니다:

```bash
npm install
```

- 처음 한 번만 하면 됩니다 (인터넷 필요, 10~20초).
- `node_modules/` 라는 폴더가 생깁니다. **이 폴더는 건드리지 않습니다.**
  용량이 크지만 `.gitignore`에 등록돼 있어서 GitHub에는 안 올라갑니다.
- `package.json`(무엇이 필요한지 목록)이나 `package-lock.json`(정확한 버전)이
  바뀌면 `npm install`을 다시 한 번 실행하세요.

---

## 3. 로컬에서 사이트 띄우기 (매번 하는 일)

```bash
npm run dev
```

- 터미널에 `Server at http://localhost:8080/` 같은 줄이 뜹니다.
- 브라우저에서 <http://localhost:8080> 를 열면 사이트가 보입니다.
- `src/` 안의 파일을 **저장하는 순간** 자동으로 다시 빌드되고 브라우저가
  새로고침됩니다. (파일 종류에 따라 브라우저를 직접 새로고침해야 할 때도 있음)
- 끝낼 때는 터미널에서 `Ctrl + C`.

영어 페이지는 <http://localhost:8080/en/> 입니다.

---

## 4. 결과물만 한 번 만들어 보기 (선택)

```bash
npm run build
```

- `_site/` 폴더에 완성된 HTML 파일들이 생깁니다. 이게 실제로 배포되는 것과
  똑같은 결과물입니다.
- `_site/`는 **자동 생성물**입니다. 여기 있는 파일을 직접 고치지 마세요
  (다음 빌드 때 덮어써집니다). `.gitignore`에 등록돼 있어 GitHub에도 안 올라갑니다.
- 지우고 싶으면 `npm run clean`.

## 5. 배포 (인터넷에 올리기)

**따로 배포 명령이 없습니다.** `main` 브랜치에 push하면 GitHub가 자동으로
빌드해서 올립니다.

```bash
git add .
git commit -m "content: 책 3권 추가"
git push
```

- push 후 GitHub 저장소 → **Actions** 탭에서 진행 상황을 볼 수 있습니다.
  초록 체크가 뜨면 완료 (1~2분).
- 잠시 뒤 <https://imbae.github.io> 에 반영됩니다.
- 빌드가 실패하면(빨간 X) 배포되지 않고 이전 버전이 그대로 유지됩니다.
  로컬에서 `npm run build`가 되는지 먼저 확인하세요.

> **Settings → Pages** 의 Source가 "GitHub Actions"로 돼 있어야 합니다.
> 한 번 설정해두면 계속 유지됩니다.

## 6. 자주 겪는 문제

| 증상 | 원인 / 해결 |
|------|-------------|
| `node`/`npm`을 찾을 수 없음 | Node 설치 전에 연 터미널. 새 터미널을 연다. |
| `npm install`이 `ENOENT ... package.json` 에러 | 프로젝트 폴더가 아닌 곳에서 실행함. `cd D:\source\imbae.github.io` 먼저. |
| `npm run dev` 후 브라우저가 빈 화면 | 터미널에 에러 메시지가 있는지 확인. 대개 `src/` 파일의 문법 오류(따옴표 안 닫음 등). 에러에 파일명·줄 번호가 나옵니다. |
| 페이지 제목만 바뀌고 본문이 안 바뀜 | 저장을 안 했거나, 다른 언어 파일(`ko`/`en`)을 고쳤을 수 있음. 두 폴더 모두 확인. |
| 빌드는 되는데 GitHub에서 실패 | 대개 `node_modules`나 `_site`를 실수로 커밋함. `git status`로 확인. |
| 제목(큰 영문 글자)이 한글만 폰트가 다르게 보임 | 정상입니다. 큰 디스플레이 폰트(Bebas Neue)가 한글을 지원하지 않아 한글은 본문 폰트로 대체됩니다. 큰 제목에는 영문/숫자만 쓰는 걸 권장. |

막히면 터미널의 에러 메시지 전체를 복사해서 물어보세요.
