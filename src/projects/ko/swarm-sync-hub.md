다수의 무인기를 하나의 지상국에서 **동시에 감시·계획·관제**하는 군사용 지상통제시스템(GCS)입니다.
통신·영상·지도·하드웨어 입력을 하나의 애플리케이션으로 통합했고, 초기 아키텍처 설계부터 개발·유지보수까지 단독으로 주도했습니다.
군사용 프로젝트라 **임무·운용·성능 세부는 공개하지 않고**, 소프트웨어 설계·구현 관점만 적습니다.
메인 앱과 5개 공용 라이브러리를 합쳐 C# 소스 파일 약 500개 규모입니다.

## 설계 과제

- **이기종 대응** — 기종·펌웨어가 다른 여러 비행제어컴퓨터와 하나의 GCS가 통신해야 해서, 특정 기종에 종속되지 않고 확장 가능한 통신 구조가 필요했습니다.
- **인지 부하** — 여러 기체를 한 화면에서 볼 때 조작자의 판단 부담을 줄이도록 상태·알람을 걸러서 보여줘야 했습니다.
- **관제권 이양의 안전성** — 여러 콘솔·조작자가 같은 기체에 동시에 명령하지 못하도록, 권한을 안전하게 넘기고 받는 절차가 필요했습니다.
- **영상 + 위치 결합** — 영상 프레임에 위치·자세 메타데이터를 표준 규격으로 기록·해석해야 했습니다.
- **다양한 입력장치** — 일반 조이스틱부터 전용 콘솔형 컨트롤러까지 하나의 조작 체계로 묶어야 했습니다.

## 1. 아키텍처 — 메인 앱 + 5개 공용 라이브러리

```
SwarmSyncHub (WPF · MVVM)
 ├─ Views / ViewModels   비행 전 준비(연결→점검→준비) · 임무 계획 · 모니터링 · 정보/파라미터 패널 · 설정 · 개발자 진단
 ├─ Controller           조종 입력 파이프라인 (장치 핸들러 · 스케일러 · 오프셋)
 ├─ Functions            상태 판정·알람 검사, 값 비교 모니터, 데이터 변환
 └─ Datas                모델·검증 규칙
        │  (Git 서브모듈, 버전 고정)
        ├─ 통신 프로토콜      Core · Flight(Uplink/Downlink 관리, 메시지, 파서, 전송) · External(외부 장치 어댑터)
        ├─ 영상               FFmpeg 디코딩 · MISB 메타데이터
        ├─ 지도               GMap.NET 커스터마이징
        ├─ 공용 UI 컨트롤     알람 다이얼로그 · 게이지 · 숫자 입력기
        └─ 공용 유틸리티      GNSS 보정신호(RTCM) 파서 · SRTM 지형 · 신호 필터
```

각 라이브러리는 **별도 Git 저장소**이고 메인 앱이 **서브모듈로 특정 버전을 참조**합니다. 이렇게 나눈 이유는 다음과 같습니다.

- **재사용** — 통신·영상·지도는 다른 GCS 제품(이전 세대 GCS, 크로스플랫폼 후속 BGCS 등)에서도 그대로 쓰입니다.
- **독립 버전 관리** — 라이브러리마다 배포·테스트 주기를 따로 가지며, 서브모듈 포인터로 어느 버전을 쓰는지 명시적으로 고정합니다.
- **관심사 분리** — 상위 애플리케이션 로직이 하위 통신·하드웨어 세부에 의존하지 않도록 인터페이스로 격리합니다.

## 2. 통신 — 3계층과 확장 지점

자체 설계한 경량 바이너리 프로토콜을 **Transport → Packet → Message** 3계층으로 나눴습니다.

- **Transport 추상화** — Serial/TCP/UDP가 달라도 상위 로직은 동일하게 동작합니다.
- **패킷 프레이밍** — 끊김 없는 바이트 흐름에서 "여기부터 여기까지가 한 메시지"라는 경계를 찾아냅니다.
- **업링크(지상→기체 명령)와 다운링크(기체→지상 텔레메트리) 채널을 분리**해 관리자·메시지 정의를 각각 둡니다.
- **`External` 어댑터 계층** — 조이스틱 여러 계열, 시뮬레이션, 계측 장치 등 외부 장치를 통신 라이브러리 안의 독립 어댑터로 두어,
  새 장치를 추가해도 비행 통신 코드는 건드리지 않습니다.

## 3. 조종 입력 파이프라인

일반 조이스틱과 전용 콘솔형 컨트롤러(Loupedeck)를 하나의 조작 체계로 묶었습니다.

- **장치 핸들러**가 장치별 입력을 받아 → **스케일러**가 축별로 값을 보정하고 → **오프셋**으로 중립점을 맞춥니다.
- **저역통과필터**로 미세한 떨림(고주파 성분)을 걸러 조종 입력을 부드럽게 합니다.
- 입력 처리를 단계별 책임으로 나눠, 장치를 바꿔도 이후 단계가 그대로 재사용되고 각 단계를 독립적으로 테스트할 수 있습니다
  (이전 세대에서 단일 클래스로 처리하던 것을 필터 → 스케일러 → 핸들러 구조로 재설계한 경험을 이어 받음).

## 4. 다중 기체 상태 표시와 관제권 이양

- **기체별 상태 모델**로 다수 기체의 텔레메트리를 동시에 유지하고, 화면에는 상태·알람을 걸러 요약해서 보여줍니다.
- **상태 판정 체계** — 검증 규칙(`ValidationRule`)과 알람 검사기가 값의 정상/경고를 판정하고, 알람은 전용 다이얼로그로 사용자에게 알립니다.
- **관제권 이양(Transfer Authority)** — 여러 조작자·콘솔 중 하나에만 기체 명령 권한을 부여하고 안전하게 넘기는 상태를 관리하며,
  편대(포메이션) 상태를 시각화합니다.
- **비행 전 준비 흐름**을 연결 → 점검 → 준비의 단계 화면으로 나눠 절차를 강제합니다.

## 5. 지도 · 지형 · 좌표

- **오픈소스 GMap.NET 커스터마이징**(기체 마커·항적 오버레이), **ProjNet**으로 좌표계 변환(위경도 ↔ 평면좌표).
- **GNSS 보정신호(RTCM) 파서**를 직접 구현했고, **SRTM 지형 표고** 데이터를 처리해 지형 정보를 함께 활용합니다.

## 6. 영상 · 메타데이터

- **FFmpeg.AutoGen**으로 저지연 디코딩, **MISB ST0601/ST0903** 영상 메타데이터를 해석해 영상 프레임과 위치·자세 정보를 함께 다룹니다.
- 영상 시작/중지에 따른 **메타데이터 버퍼의 수명·초기화**를 관리해, 이전 영상의 정보가 다음 영상에 남지 않도록 했습니다.

## 7. 저장 · 로깅 · 진단

- **Serilog** 구조화 로깅, **SQLite / MongoDB.Bson**으로 로컬·문서 기반 저장, **CsvHelper / Newtonsoft.Json**으로 임무·설정 직렬화.
- **개발자 진단 화면(Dev Tools)** 으로 기체별 실시간 상태를 확인해, 현장 이슈를 빠르게 재현·분석합니다.

## 8. 운영하며 다룬 문제

실제 운용에서 나온 **계산 오차, 라이브러리 버전 호환성, 동기화 오류**를 분석하고 수정하며 실운용 수준의 안정성을 확보했습니다.
서브모듈로 버전을 고정하는 구조는 호환성 문제를 "어느 조합에서 깨졌는가"로 좁혀 원인을 찾는 데 도움이 되었고,
영상·위치처럼 시간이 어긋나기 쉬운 데이터는 상태 수명을 명시적으로 관리하는 쪽으로 정리했습니다.
