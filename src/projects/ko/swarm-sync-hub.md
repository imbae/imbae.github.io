다수의 무인기를 하나의 지상국에서 **동시에 감시·계획·관제**하는 군사용 지상통제시스템(GCS)입니다.
통신·영상·지도·하드웨어 입력을 단일 애플리케이션으로 통합했고, 초기 아키텍처 설계부터
개발·유지보수까지 단독으로 주도했습니다. 군사용 프로젝트라 **임무·운용 세부는 공개하지 않고**
기술 설계 관점만 적습니다.

## 설계 과제

- **이기종 대응** — 기종·펌웨어가 다른 여러 비행제어컴퓨터와 하나의 GCS가 통신해야 해서, 특정 기종에 종속되지 않는 통신 구조가 필요했습니다.
- **인지 부하** — 여러 기체를 한 화면에서 볼 때 조작자의 판단 부담을 줄이도록 상태·알람을 걸러 보여줘야 했습니다.
- **관제권 이양의 안전성** — 여러 콘솔이 동시에 같은 기체에 명령하지 못하도록, 권한을 안전하게 넘기고 받는 절차가 필요했습니다.
- **영상 + 위치 결합** — 영상 프레임에 위치·자세 메타데이터를 표준 규격으로 기록/해석해야 했습니다.

## 아키텍처

메인 앱과 **5개의 재사용 가능한 사내 공용 라이브러리**로 구성한 모듈형 구조입니다. 각 라이브러리는 별도
저장소이고 메인 앱에서는 **Git 서브모듈**로 특정 버전을 참조합니다.

| 라이브러리 | 역할 |
|---|---|
| 통신 프로토콜 | Transport · Packet · Message 3계층 분리, Serial/TCP/UDP, 업링크·다운링크 채널 분리 |
| 영상 처리 | FFmpeg 기반 저지연 디코딩, MISB ST0601/ST0903 영상 메타데이터 |
| 지도 | 오픈소스 GMap.NET 커스터마이징, ProjNet 좌표계 변환 |
| 공용 UI 컨트롤 | 알람 다이얼로그·게이지·숫자 입력기 등 디자인시스템 요소 |
| 공용 유틸리티 | GNSS 보정신호(RTCM) 파서, SRTM 지형 표고, 신호 필터링 |

**이렇게 나눈 이유** — 재사용(다른 GCS 제품에도 적용), 독립적 버전 관리, 관심사 분리(상위 로직이 하위 통신·하드웨어 세부에 의존하지 않도록 인터페이스로 격리).

## 주요 구현

- **통신** — 자체 설계 경량 바이너리 프로토콜. Transport 추상화로 연결 방식이 달라도 상위 로직이 동일하게 동작합니다.
- **UI** — WPF + MVVM(CommunityToolkit.Mvvm), 다중 기체 상태를 유지보수하기 쉬운 구조로 표시.
- **지도·지형** — 기체 위치·경로 표시, RTCM 보정신호 파서와 SRTM 지형 데이터를 직접 구현/연동.
- **영상** — FFmpeg.AutoGen 저지연 디코딩과 MISB 메타데이터 해석.
- **입력장치 통합** — 조이스틱(DirectInput)과 전용 콘솔형 컨트롤러를 하나의 조작 체계로 묶고, 저역통과필터로 조종 입력의 떨림을 제거.
- **다중 기체 관제** — 다중 조작자 간 관제권 이양 상태 관리, 편대 상태 시각화.
- **로깅·진단** — Serilog, SQLite/MongoDB.Bson 저장, 개발자 진단 화면(Dev Tools)으로 실시간 상태 확인.

## 운영하며 다룬 문제

실제 운용 중 발생한 계산 오차, 라이브러리 버전 호환성, 동기화 오류 등을 분석하고 수정하며 실운용 수준의 안정성을 확보했습니다.
